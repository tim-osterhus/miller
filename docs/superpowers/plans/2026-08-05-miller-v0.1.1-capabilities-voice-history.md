# Miller v0.1.1 Capabilities, Voice History, and Interaction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Miller v0.1.1 with durable and explicitly reviewable Live Voice transcripts, selectable transcript text, user-respecting streaming auto-scroll, portable MCP tools, Codex account capabilities in typed and voice modes, per-server and per-tool policy, and tabbed settings.

**Architecture:** SQLite remains the only durable Miller authority. A Swift-owned capability broker discovers and executes owner-configured MCP servers, applies policy, and writes sanitized audit records. A narrow bundled MCP adapter lets ordinary Codex App Server turns and GPT-Live call that same broker without using experimental dynamic-tool APIs; Pi uses the existing bounded JSONL gateway to request the same broker. Codex account apps remain Codex-executed and Codex-only. Presentation work is isolated into reusable follow-tail, selection, history, approval, and tabbed-settings components. The completed Sherpa-ONNX wakeword foundation remains source-only for v0.1.2 and contributes no binary or runtime feature to v0.1.1.

**Tech Stack:** Swift 6.1, SwiftUI/AppKit on macOS 15, SQLite, official Model Context Protocol Swift SDK 0.12.1, strict local Unix-domain-socket RPC, Node.js 22.22.0, the existing pinned Pi overlay, external OpenAI-signed Codex CLI, Swift Testing, Node test runner, and zsh packaging and qualification scripts. Sherpa-ONNX 1.13.2 and ONNX Runtime 1.24.4 remain explicit source-qualification inputs for the deferred wakeword foundation and are not v0.1.1 runtime dependencies.

## Stable shared contracts

Implement these names once and reuse them throughout the plan:

```swift
public struct CapabilityID: Hashable, Codable, Sendable, CustomStringConvertible {
    public let rawValue: String
    public var description: String { rawValue }
}

public enum CapabilitySource: String, Codable, Sendable {
    case codexAccount = "codex_account"
    case millerMCP = "miller_mcp"
    case providerNative = "provider_native"
}

public enum CapabilityPolicy: String, Codable, Sendable, CaseIterable {
    case readOnlyAutomatic = "read_only_automatic"
    case askBeforeChanges = "ask_before_changes"
    case fullyTrusted = "fully_trusted"
}

public enum CapabilityTerminalOutcome: String, Codable, Sendable {
    case succeeded, failed, declined, cancelled, timedOut = "timed_out"
}

public struct CapabilityCallID: Hashable, Codable, Sendable {
    public let rawValue: UUID
}
```

Capability identifiers use `source/server/tool`, lowercase ASCII, and a maximum of 192 UTF-8 bytes. Tool names, server IDs, descriptions, input schemas, call arguments, results, and audit summaries must be bounded before crossing a process or persistence boundary.

Policy semantics are fixed for implementation:

| Effective policy | Declared read-only call | Declared state-changing or unknown call |
| --- | --- | --- |
| Read-only automatic | Execute automatically | Decline as policy-disabled |
| Ask before changes | Execute automatically | Require owner approval |
| Fully trusted | Execute automatically | Execute automatically unless provider/managed policy mandates approval |

New owner-added MCP servers are enabled for compatible providers after a successful connection test and default to **Ask before changes**. Imported plugin MCP definitions remain disabled drafts until reviewed. Codex account capabilities inherit Codex availability and mandatory policy; Miller never silently weakens it.
